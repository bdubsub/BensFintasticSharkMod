## Architecture and Implementation Boundaries

- Keep the logical server authoritative for movement decisions, targeting, damage, grabs, replacement, population, advancement criteria, and world generation. Client evidence verifies presentation and synchronized state only.
- Keep `net.minecraft.client` references inside the existing Forge client boundary. Dedicated-server ready state must prove common initialization, registration, data loading, and test seams do not load client classes.
- Treat Forge datagen providers as authoritative for generated resources. A hand-edited file under `common/src/generated/resources` without a matching provider contract is drift.
- Preserve stable identifiers and save compatibility. Retirement of `bensfintasticsharks:shark_whisperer` is the sole planned identifier removal, with no progress migration because `sharks_galore` has equivalent criteria.
- Keep runtime evidence bound to source commit, JAR hashes, game and loader versions, config, data packs, seed, world or profile, players, duration, coordinates, and logs. Do not combine evidence from different candidates.
- Preserve exact supplied artwork, animation bones, clip intent, algae frame order, and repeated visual holds. Structural existence never substitutes for sampled motion or interactive rendering.
- Keep population and world-generation work bounded. Tests must use controlled tick budgets and samples; production paths must not add unbounded scans, per-tick filesystem access, or noisy logs.
- Treat configuration, data packs, NBT, entity targets, packet or synchronized state, and archive contents as untrusted inputs. Validate type, side, bounds, lifecycle, and namespace before mutation.
- Preserve the unsupported Fabric stub as a non-release module. Its known SmartBrainLib failure is recorded separately and cannot waive, fail, or redefine the Forge release gate unless Phase 005 worsens it.

| Class | Examples and release condition | In-scope route | Material-change route |
|---|---|---|---|
| Startup and registration | Crash, registry failure, data-pack failure, tag, loot, recipe, advancement, feature, or animation reference load failure | Repair existing `0.24` implementation and rerun data, build, server, and affected runtime gates | `PLAN_REVISION_REQUIRED` if the fix changes public IDs, platform, dependencies, or compatibility |
| Side and security boundary | Dedicated-server client-class load, unvalidated state mutation, unsafe archive or path handling, secret exposure | Restore existing side separation or validation and rerun server, security, and package audits | Stop for new trust model, credentials, permissions, paid capability, or destructive behavior |
| Networking and persistence | Desync, leaked passenger or camera state, disconnect or dimension cleanup failure, save loss | Repair master-defined server authority and cleanup; test disconnect, reconnect, death, unload, and dimension change | Stop for protocol redesign, save-breaking migration, or externally visible compatibility choice |
| Entity movement and combat | Nonmoving required entity, unreachable bite, duplicate damage, stuck curiosity, stale target | Repair defined movement, reach, timing, cooldown, and recovery; rerun deterministic, GameTest, client, and multiplayer gates | Stop if intended balance, prey scope, or authored behavior is not determined by the master |
| Animation and rendering | Static required clip, missing bone, wrong controller priority, stale thrash, armor collision, atlas warning | Restore authored transforms, state mapping, and presentation; rerun sampling and interactive review | Stop for new unauthored animation or art direction |
| Replacement and population | Wrong source type, more than one replacement, category mismatch, flood, suppressed unrelated mob | Restore exact allowlist, one-for-one invariant, fail-closed behavior, and bounded spawn path | Stop for new population policy or conversion scope |
| Advancement and copy | Dead end, cycle, retired node present, missing child edge, changed criteria, wrong title, punctuation, or icon | Restore exact graph, copy, icon, and criteria contract; regenerate and rerun fresh profile | Stop for new progression, reward, localization policy, or compatibility migration |
| Algae and world generation | Missing content, invalid survival, land placement, structure replacement, navigation barrier, flood, nondeterminism | Restore specified blocks, tags, codecs, placement, survival, loot, density, and rendering | Stop for new ecology, biome lore, distribution policy, or public content unit |
| Version, documentation, and package | Mixed version, stale claim, wrong loader artifact, missing asset, bad hash, incomplete SBOM or attestation | Correct release metadata, docs, allowlist, and provenance; rebuild and rerun affected gates | Stop for licensing, publication target, artifact type, or owner approval change |

A reproducible finding that violates any stable requirement is release blocking regardless of where it was discovered. A minor unrelated cosmetic observation may be deferred only when evidence proves it violates no requirement or acceptance criterion; record it in ordinary issue tracking with exact reproduction and scope rationale. Unknown severity remains blocking until classified. Never weaken a test or relabel a known defect to pass release.

An in-scope repair is one whose expected result is uniquely determined by the master and preserves project identity, versions, public behavior, compatibility, trust boundaries, and owner decisions. Any fix requiring a new material decision stops immediately with `PLAN_REVISION_REQUIRED`, naming the affected stable IDs, observed evidence, available choices, and decision needed. No phase file or master requirement is edited to absorb the change.
